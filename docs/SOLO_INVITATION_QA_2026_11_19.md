# Solo-user QA — invitation and sharing (19 November 2026)

## Scope
No Supabase migrations. QA/Production `space_invitations` already allow the
creator to SELECT their own invitation under RLS. Never expose another
person's invitation. Do not modify paired accounts or release markers.

## Acceptance checklist

1. Sign in on QA Android with exactly one space member; Today shows a compact,
   **collapsed** invitation card with a single primary action.
2. When no invitation exists: primary CTA is **Create invitation code**.
   Tap it. An invitation is created; dialog offers WhatsApp, SMS, email,
   copy, QR and the manual code. No additional code is generated by sharing.
3. With an outstanding invitation: primary CTA is **Resend invitation**.
   Tap it three times and compare codes and original expiry: both remain
   identical. Confirm server has no new `space_invitations` row.
4. Expand the card. **Generate a replacement code** opens a confirmation.
   Cancel leaves the first invitation active. Confirm makes the old code
   unusable immediately, and a distinct new code is shown.
5. Expand and revoke. The invitation stops working and Today again offers
   **Create invitation code**.
6. Email/WhatsApp/SMS: readable invitation, branded first-party landing URL,
   original code for manual fallback; email includes Google Play and App Store
   placeholders. If the device has no configured messaging application,
   display a useful failure message and offer copy.
7. Open the link in a recipient's **matching environment** (QA vs production).
   Tap **Open in OneSpace**. With the app installed, the app opens and
   prepopulates Join your partner; do not auto-accept. Sign in if required,
   then confirm Join space. A code cannot be accepted twice.
8. Open the same link without the app installed. The page explains how to
   install later or manually copy the code; it must not claim the store
   releases are already available.
9. Test wrong-environment links, tampered codes, expired invitations,
   self-invitation, unpaired recipient and an account already paired.
10. Repeat on iPhone and verify URL-scheme registration before shipping.
    Browser auto-opening via verified HTTPS links additionally requires
    Android assetlinks.json signed certificate association and iOS AASA
    Team ID / Associated Domains; do **not** claim this works until verified.

## Release policy
One reviewed release per iteration. This branch intentionally does not
change a release marker or publish an APK.

## Password-manager and recovery regression

1. On a device where Google Password Manager stores a OneSpace password,
   open Me → Profile → Change password. The current-password field advertises
   the platform autofill hint; Android and iOS may offer the saved credential
   after the user taps it. App code must never extract a Google password.
2. Check current password remains obscured. The app never logs, persists, or
   pre-populates it from session tokens.
3. Incorrect current password must fail without changing account credentials.
   Matching new password and confirmation of length >=8 is required. Server
   leaked-password protection and policy remain authoritative.
4. Tap "Forgot current password? Send a reset email"; it calls Supabase Auth
   with the signed-in user's email and environment-specific redirect. Verify
   the email arrives on QA, and its link reaches the OneSpace password-recovery
   screen, then requires sign-in with the new password.
5. Repeat the reset on Production with a separate test account. Never email
   secrets or use a production account to test QA.
6. Verify reset-email rate limiting, no account enumeration, no password
   stored in SharedPreferences, and temporary input controllers are disposed.
7. Test both system light/dark, Arabic/English, Android/iPhone.
